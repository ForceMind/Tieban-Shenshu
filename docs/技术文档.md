# 技术文档（开发者）

面向维护者：系统架构、模块职责、数据结构、Python→JS 移植与校验、发布构建。

## 架构总览

自 v3.0 起为**纯前端**，无后端。浏览器内完成八字换算与全部推演。

```
index.html  ──表单──▶  window.calculateTieban(formData)
                          │  (js/tieban.js)
                          ├─ convertToBaziInfo()  ← js/lunar.js（历法）
                          └─ calculate()          ← window.TIEBAN_DB（js/db-data.js）
                          ▼
                     result 对象 ──存 localStorage──▶ result.html / Print.html 渲染
                                                         └─ 断语白话 ← js/duanyu-modern.js
```

Python 版（`main.py` + `server.py`）保留为**参照实现**，不参与部署。

## 文件职责

| 文件 | 职责 |
|---|---|
| `index.html` | 输入表单；提交时本地调用 `calculateTieban`，结果存 localStorage 后跳转 |
| `result.html` | 从 localStorage 读结果并渲染（基础盘、卦象、本命条文、流年表） |
| `Print.html` | 打印版渲染（单表 1-100 岁） |
| `js/lunar.js` | lunar-javascript 库，替代 Python 的 cnlunar 做农历/八字换算 |
| `js/db-data.js` | 由 `DB/*.csv` 导出的全部数据，挂 `window.TIEBAN_DB` |
| `js/tieban.js` | 核心算法，移植自 `main.py`，暴露 `window.calculateTieban` |
| `js/duanyu-modern.js` | 断语→现代白话字典，挂 `window.DUANYU_MODERN` |
| `js/terms.js` | 排盘术语白话解释字典（20 词条），挂 `window.TIEBAN_TERMS` |
| `favicon.svg` | 网页图标（朱砂红圆角方块 + 白色「铁」字） |
| `tools/build.js` | 发布构建（混淆 + 压缩） |
| `main.py` | 参照实现：算法 + 数据加载器（`TieBanCalculator` / `TieBanDataLoader`） |

## API 契约（前端内部）

`calculateTieban(formData)` 返回与旧后端 `/api/calculate` 完全一致的结构：

```js
formData = { gender:"男", birth:{year,month,day,hour,minute}, query:{...}, six_qin_info:{} }
返回     = { success:true, info_b, info_q, gender, result }
```
- `info_b/info_q`：八字信息 `{lunar_month, lunar_day, is_leap, bazi:{year,month,day,time}, date_str, lunar_str}`
- `result`：见 `calculate()`，含 `cong_num/tone_num/moment_cn/main_num/hex_name/pn_num/san_yuan/tbl_data/liunian[...]` 等

> 六亲考刻（Step 9）在参照实现中已注释禁用，故当前不在计算范围内。

## 八字换算：cnlunar → lunar.js 映射

经 1300+ 例逐柱校验确定的等价映射：

| 柱 | cnlunar | lunar.js |
|---|---|---|
| 年 | year8Char | `getYearInGanZhi()` |
| 月 | month8Char | `getMonthInGanZhi()` |
| 日 | day8Char | `getDayInGanZhiExact()`（23:00 进日） |
| 时 | twohour8Char | `getTimeInGanZhi()` |

`lunar_month = abs(getMonth())`、`is_leap = getMonth()<0`、`lunar_day = getDay()`。
`lunar_str` 复刻 cnlunar 格式：年用「零」数字，月名正/二…十/冬/腊 + 大(30日)/小(29日)，闰月加「闰」。

## 数据结构（`window.TIEBAN_DB`）

Python 的**元组键**字典在导出时用 `|` 拼接为字符串键，数字键转字符串：

| 键 | 形如 | 值 |
|---|---|---|
| `tables['14-1'...'14-6']` | 普通表 | 数值/嵌套对象 |
| `HEXAGRAM_MAP` | `"181"` | 卦名 |
| `HEXAGRAM_DETAIL_MAP` | `"初刻\|181"` | 卦名 |
| `DESTINY_DATA` | `"复\|Main\|8"` | `{base,seq,offsets{类别:[偏移]}}` |
| `LIUNIAN_START` | `"generic\|寅午戌\|男"` | 起始数 |
| `LIUNIAN_SEQ` | `"1\|甲"` | 12 元五音序列 |
| `MARKER_TABLE` | `"子"` → `{"1":"开",...}` | 标记 |
| `LETTER_TABLE` | `"初刻\|奇数\|四\|开"` | 字母 |
| `DATA_BY_LETTER` | `"福\|1"` | `[base,add,校正数]` |
| `DATA_BY_CORRECTION` | `"1\|1"` | `[base,add]` |
| `CORRECTION_TO_LETTER` | `"1\|1"` | 字母 |
| `FORTUNE_DUANYU_MAP` | `"1001"` | `[断语, 年龄]` |
| `rule_tables` | 数组 | `{组别,和值条件,刻别}` |

## Python→JS 移植与校验方法

移植目标：JS 输出与 Python 参照实现**逐字节一致**。校验分两轨：

- **Track A（八字换算）**：对 1344 个日期（含立春/节气/子时/闰月边界）比对 cnlunar 与 lunar.js 的四柱及农历字段——全通过。
- **Track B（calculate）**：把 cnlunar 产出的**相同** `birth_info/query_info` 同时喂给 Python 与 JS 的 `calculate`，深比较完整 `result`（覆盖八刻全分布、五数寄宫、三元九运、卦名回退等分支，173 例）——全通过。

复现思路：用 `main.py` 生成 ground truth JSON，Node 加载 `js/*.js` 跑同输入，深比较。断语白话字典亦经逐批 1:1 等长与全覆盖校验。

## 发布构建（`tools/build.js`）

```bash
npm i terser javascript-obfuscator html-minifier-terser
node tools/build.js      # 产物在 tools/dist/
```

策略（按文件性质分治）：

| 文件 | 处理 | 原因 |
|---|---|---|
| `js/tieban.js` | 混淆（含控制流平坦化、字符串数组） | 核心算法，值得保护 |
| HTML 内联脚本 | 混淆（`renameGlobals:false`） | 保护渲染逻辑，同时保留 `window.*` 与 onclick 引用的顶层函数名 |
| `js/lunar.js`/`db-data.js`/`duanyu-modern.js`/`terms.js` | 仅压缩（terser） | 大数据文件完整混淆会 2~3 倍膨胀且无实质保护 |
| HTML | 压缩 | — |
| `favicon.svg` | 直接复制 | SVG 无需处理 |

**关键约束**：`renameGlobals:false` 必须开启，否则会改坏 `window.calculateTieban`、`window.TIEBAN_DB` 访问及 onclick 引用的全局函数。

构建后验证：混淆产物在沙盒中计算结果与源码一致（多样本），jsdom 渲染确认公历年与白话正常显示。

> 纯前端无法真正加密：代码与数据最终都要在浏览器执行，混淆仅提高逆向门槛。

## 重新导出数据（如修改 DB/*.csv）

`js/db-data.js` 由 `DB/*.csv` 导出。`db-data.js` 顶部注释提及 `tools/export_db.py`（当前仓库未含该脚本）；如需重新导出，可参照 `main.py` 的 `TieBanDataLoader._load_all()` 构建同结构后按上表 `|` 键编码序列化。
